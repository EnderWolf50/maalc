name: maalc-gui-check
description: Build and launch the real maalc settings app (Tauri, gui/) and drive the changed controls: clicks, typing and selects with cua-driver in background delivery; drags, held presses, keys with modifiers, the light scheme, a page size and positions with tools/gui_devtools.mjs over DevTools. Use when a change touches gui/, tauri.conf.json, the settings schema or anything the settings window shows, before calling it verified.
---

`pnpm test`, `tsc` and `tauri build` never open the app. A Tauri window setting (`dragDropEnabled`) once broke every drag-and-drop list while each earlier GUI PR passed those three (issue #64, fixed in 380aad8). A GUI change is verified when the real app was driven and looked at.

Two tools act on the window (`docs/agents/gui-driving.md` "cua or DevTools"): cua-driver in background delivery for what a user's click, typing, select or scroll does, and `tools/gui_devtools.mjs` over the page's DevTools port for what background delivery cannot do: a held press, a drag, keys with modifiers, the light or dark scheme, another page size, an element's box, a masked still of the page. What driving it takes (session, delivery mode, window sizes, UIPI) is in `docs/agents/gui-driving.md`; how the screenshots look is in `docs/agents/evidence-style.md`. Read `cua-driver`'s skill before step 4. The app runs from a throwaway folder: the emulator, the game account and `install/` are not involved, and no live-test queue ticket is needed.

## Steps

1. **Scope.** List the controls the change can reach and the input each needs: a click, typing, a select, a drag. A change to `tauri.conf.json`, `lib.rs`, `ui.tsx`, `Plans.tsx`, `ThemePacks.tsx` or CSS that can move a hit target counts as reaching every drag-and-drop list (the team list, the plan lists). Done: the list exists, each control with its input.
2. **Build.** In your worktree: `pnpm --dir gui install --frozen-lockfile`, then `pnpm --dir gui tauri build --no-bundle` (about 3 minutes cold), as a background command waited on. Done: `gui/src-tauri/target/release/maalc-gui.exe` is newer than your last edit of `gui/`.
3. **Launch.** `uv run python tools/gui_probe.py --exe gui/src-tauri/target/release/maalc-gui.exe --root <main checkout>/.local/scratch/<task>/gui-root` (find the main checkout's `.local/` with `tools/local_dir.py`; a different `--settings FILE` starts the app on a file the change needs). It copies the exe beside demo settings, starts it and prints `{"pid", "hwnd", "rect", ...}`. Keep the pid. Done: the probe exited 0 and printed a pid; a blank window or exit 1 means the build or the settings are wrong, or that `--root` exists without the probe's marker file (a folder the probe did not make is never deleted: pick a new `--root` or remove the old one yourself), so read why before going on. When step 1 lists a drag, a hold, a key with modifiers, a scheme or a size, launch with `node tools/gui_devtools.mjs open --root <same root>` as a background command instead: the same root and settings (`--settings FILE`), and it prints `{"pid", "hwnd", "port", ...}`; `hwnd` is cua's `window_id`, and cua acts on this window as on the probe's. Done: it printed that line; an error line names what failed.
4. **Observe.** With one `"session":"<task>"` on every cua call: `get_window_state` with `include_accessibility_tree:false` and `--screenshot-out-file` gives the window's screenshot (never `get_desktop_state`, never a screen capture). Its pixels are the coordinates of every cua action. `gui_devtools.mjs still <png> --mask "header .path" --port <port>` takes the page alone, its path blacked out, in a scheme or size its `--scheme` and `--viewport` set. Done: `before-*.png` of each screen the change touches.
5. **Drive.** Pass `delivery_mode:"background"` on every input call (`click`, `type_text`, `press_key`, `scroll`, `drag`): background input leaves the user's cursor and focused window alone while they work. For each control of step 1: act, then take a new screenshot; the driver's own `effect` is `unverifiable` for drags and says nothing. Clicks, typing, selects and scrolling work in background (`docs/agents/gui-driving.md` "Input"). What background delivery cannot send goes through `tools/gui_devtools.mjs` on the port step 3 printed, never foreground delivery: a drag (`drag <from> <to> --then <check>`: check the order changed and "有未儲存的變更" shows), a held press (`press <target> --hold 150`, `--move 0,40` to move while held), keys with modifiers (`key Shift+Tab`, which prints what has the focus after), the light scheme (`scheme light` in the background while a cua still is taken, or `--scheme light` on a `still`), a size (`--viewport 800x480`), a position (`box <selector>`). A DevTools drag runs the page's own drag-and-drop with its hit testing but not Windows' drag-and-drop, so a drag's verdict also names `gui/src/dragSort.test.ts` passing (`pnpm --dir gui test`), which keeps the window setting that once broke every list (#64). Foreground delivery moves the user's cursor, so a foreground action runs only after the user says yes in chat to that one action, and the next one asks again. Done: each control has an after screenshot and a verdict (works / does not / not reached), and a control that did not work is reported, not retried until it does.
6. **Mask and stop.** The app's header shows the full path of `settings.json`: black it out, and anything else identifying, in every screenshot (`docs/agents/evidence-style.md` "Privacy"). Stop the app with `taskkill /T /F /PID <pid>` in PowerShell, the pid of step 3 only; an app `gui_devtools.mjs open` started stops with that command (stop the background task, or `node tools/gui_devtools.mjs close --root <root>`). Done: `Get-Process -Id <pid>` finds nothing, and the screenshots hold no path, e-mail or account name.
7. **Report.** Per control: verdict, with its before and after stills, attached to the PR (`gh pr create/comment --attach '<file>#<alt>'`, AGENTS.md "Public repo"). A control not driven says so and why. Done: the PR body's Verification section names, with the stills, the controls driven, by cua or by `gui_devtools.mjs`, each drag with `dragSort.test.ts` passing, and the controls not driven.

Not run (say so, do not claim it verified): a PR that could not build the app, found no window, or ran with the driver and the app at different integrity levels.
