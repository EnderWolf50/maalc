name: maalc-live-test
description: Run maalc against the MuMu emulator and report it with evidence. Use for a live test, an experiment, live verification of a PR, or an unattended run on the emulator.
---

A **live test** drives the user's real game account. It owns the emulator alone, starts from a known screen, and leaves the account, the game settings and `install/` as it found them. Emulator settings (resolution, window) stay the user's. Machine-local state lives in `.local/` of the main checkout, never of your worktree (`docs/agents/local-dev.md`); `install/` is the main checkout's too.

The tools are in `tools/live/`, each with its options in `--help`. Reach for them before writing a script:

| Tool | Does |
| --- | --- |
| `queue.py` | the emulator and bench tickets, `detach`, `status`, `resume` |
| `backup.py hold` | backs up `install/` and verifies it after the run |
| `bot.py` | `run` the bot headless into a stamped `run.log`; `prep` a test install's settings; `awake` keeps the screen on |
| `device.py` | `shot`, `tap`, `key`, `start` an app; `freeze` the bot on a log line to look or act, then resume |
| `evidence.py` | `events`, `steps`, `frames`, `clip`, `mask`; `map` and `packs`, the route and pack evidence of step 8 |
| `maafw_events.py` | maafw.log touches as events.json |
| `dialogs.py` | the game's confirm dialogs, to diff against the pipeline before an unattended run |

Log statistics: `tools/wait_spans.py` (Now Loading and other waiting screens), `tools/maafw_timeline.py` (time per node), `tools/video_align.py` (a recording against the log, its drift and freezes). A one-off script none of these covers goes in `.local/scratch/<task>/`; `docs/agents/live-tools-inventory.md` lists which old scripts the tools replaced.

Recording and annotation come from two global skills: `screen-record` and `evidence-annotate`. Read each before its step.

Resolve output paths through `tools/local_dir.py` before starting a process: `.local/` below means the main checkout's folder. New probe scripts and cache go in `.local/scratch/`; `.local/probe/` holds the migrated historical scripts, environments and captures. See `docs/agents/local-dev.md` before migrating or removing old compatibility paths; another task's recording must finish first.

## Steps

0. **Resume.** Whenever your turn (re)starts, including after a rate limit, an error or a "continue" message, run `uv run python tools/live/queue.py resume --task <task>` first and act on its `next:` line; never re-arm a wait for a bot that already ended (it finishes the run while no agent watches, and the recording and the emulator stay held). Done: you know whether hold and bot run, whether `done` exists, and which step is next.
1. **Queue.** Use a fresh `<task>` name each run (its `.local/scratch/<task>/` folder holds the logs `resume` and `status` read). Take the emulator with the one non-interactive command, detached so it outlives the harness (which kills a background command after 2 hours): `uv run python tools/live/queue.py detach --log .local/scratch/<task>/hold.log -- uv run python tools/live/queue.py run --resource emulator --name <task> -- uv run python tools/live/backup.py hold --label <task> --done .local/scratch/<task>/done --guard '.local/scratch/<task>/bot*.log' [--stop-recording <screenrec profile>]`. The glob takes in every bot run of the hold (`bot.log`, then `bot-b.log`, ...), so a second run keeps the timeout and the recording going. With the flag, `hold` stops that recording 60 s after the bot ended, so a run nobody watched does not leave it growing; it logs `[hold] bot ended <time>` either way. `queue.py status` marks a holder whose bot ended over 10 min ago with no `done` file as waiting for the agent. The detach returns at once with a pid. Without a `done` file `hold` gives up after `--timeout` (default 2 h), counted from the end of the bot of step 6 (`--guard`), never while it runs. `hold` backs up `install/` (an md5 manifest and a copy of `settings.json`), waits until the `done` file exists, then verifies `install/` against the backup. The queue is first-come-first-served and drops dead holders; while another task holds the emulator you wait on `hold.log` with one Monitor until-loop (re-arm it if it times out; the hold keeps its place), so keep your turn open. Steps 2, 5, 6 and 8 are your own actions, taken while the command holds the emulator. Done: `hold.log` shows `[queue] start <task>` and `backed up <n> files`.
2. **Pre-flight.** Screenshot the emulator. Main screen with no resumable Mirror Dungeon run → go on. A resumable run, any other screen, an update or a download prompt → stop and ask; forfeiting a run is the user's call and never goes through Queue. Done: `00-start.png` shows the main screen.
3. **Scope.** Run the segment each check needs (a few decisions), not a whole dungeon, unless the brief names a full run. Done: every check in the brief names the segment that exercises it.
4. **Settings.** Write down every game setting you will change, with its value now. Done: the list exists in your notes.
5. **Record.** `screen-record`: `screenrec.py start --window <title substring> --height 720 --out .local/archive/<date>-<topic>/ [--profile <name>] [--crop-top N] [--keep-gb N]`. Always pass `--height 720`: without it the clip has the window's own size (about 1400p, 11 Mbps), which piled up 62 files and 171 GB on 2026-10-29, and MaaFramework reads the screen at 720p anyway. The existing 720p HEVC recordings average about 1.4 Mbps, so budget about 0.6 GB an hour (computed from that average, not measured per run); the x264 fallback is larger. A run that may outgrow its budget passes `--keep-gb` above its expected size (`--keep-gb` prunes the oldest `rec_*.mp4` in `--out` only). To keep a recording under `.local/archive/recordings/`, make a hard link (`New-Item -ItemType HardLink -Path .local/archive/recordings/<name>.mp4 -Target <rec>.mp4`), never a copy. It refuses no visible window, a minimised one, a profile already recording, less than 30 GB free (`--min-free-gb`), a black first frame, and no frame within 10 seconds, which is what a sleeping display gives: with the monitor off, Windows draws nothing to capture, so a recording needs the user's screen awake. Pass the same `--profile` to `status` and `stop` as to `start`. Done: `screenrec.py status [--profile <name>]` prints `active True`.
6. **Run.** Start the bot the way the brief says, through `uv run python tools/live/queue.py detach --log .local/scratch/<task>/bot.log -- <bot command>` (the `--guard` of step 1), never as a plain background command; it prints the pid. A later bot run in the same hold goes under its own `bot-<x>.log`, which the guard's glob follows. The bot command is `uv run python tools/live/bot.py run --install <install> --log .local/scratch/<task>/run.log` unless the brief names MXU: step 8 reads `run.log`. Wait with one Monitor until-loop on `uv run python tools/live/queue.py status --log .local/scratch/<task>/bot.log` (exit 0 running, 1 ended); a Monitor that times out ends only the wait, so re-arm it. Your turn stays open until the run ends. Done: the run ended or hit the brief's time limit.
7. **Stop.** `pwsh tools/live/stop_run.ps1 -RunPid <pid>` takes the whole process tree; then `screenrec.py stop [--profile <name>]`. Done: `stop_run.ps1 -WhatIf` lists no process, and `stop` printed `saved <file>.mp4` with its `started` time, which is step 8's `--start` exactly (frames carry their wall-clock capture time; no `--offset` needed). If `hold` already stopped the recording (`--stop-recording`), `stop` finds none: take `saved` and `started` from the `hold.log` output of that stop.
8. **Evidence.** Everything leaves `.local/` masked by `.local/evidence/masks.json`, which blacks out the three identity regions: the player-number plate, the player name above the LV panel at the bottom left (36,626,98,20 in game pixels) and the account e-mail; `evidence.py` applies it to every still and clip it writes. Below, every command runs as `uv run --group probe python tools/live/evidence.py`, `<rec>` is `--video <mp4>@<started>` from step 7 (one per piece of a run recorded in pieces) and `<out>` is `.local/archive/<date>-<topic>/`.
   - **Route, every floor played**: `map .local/scratch/<task>/run.log <rec> --floor N -o <out>/f<N>/route --clip` writes `stitched.png` (the whole floor from the frames before and after each drag, every node the bot read boxed with its type and Cost, special reads (boss by glow or shop, Cost miss, retyped) in their own colour with a legend, the route numbered), `before-1.png`, `after-N.png` and `drag-clip.mp4`. Judge each node of `stitched.png` against the frames: a wrong type, a wrong Cost or a node the bot did not list goes into a FIX file (its form is in `evidence.py --help`), and a rerun with `--fix FIX.json` marks it red or orange. A floor read again after a restart: the same command with `--after <time of the restart line>`.
   - **Packs, every floor played**: `packs .local/scratch/<task>/run.log <rec> --floor N -o <out>/f<N>/packs --clip` writes a `pack-K.png` per reading, refreshes included (each card's name and weight, the pulled card's thick border, the seconds from the deal to the cards standing still), and `pack-K-clip.mp4`.
   - **Other checks**: `events` and `steps` turn `run.log` into evidence-annotate's events and captions (`maafw_events.py` reads a maafw.log, the main checkout's), then `evidence-annotate`: `annotate.py VIDEO -o OUT --start <started> --events events.json [--steps steps.json] --masks .local/evidence/masks.json [--from T --to T] [--frames T,…]`. A device screenshot goes through `evidence.py mask` before it is shared.
   - **Post**: each floor's route stills and drag clip to #251, its pack stills to #252 (`gh issue comment <n> --attach '<file>#<alt>'`), or to the PR the run verifies. Add one row to `.local/archive/INDEX.md`.

   Done: every check of the brief has its annotated clip; each floor played has a `stitched.png` with every node it read boxed and judged, a drag clip and a `pack-K.png` per pack reading, posted to #251 and #252 (or the PR); the INDEX row exists.
9. **Restore.** Game settings back as written down in step 4, then create the `done` file of step 1 (the Write tool). `hold` verifies `install/` and the queue command ends. Done: `hold.log` ends with `install matches the backup (md5)` and `queue.py status --log .local/scratch/<task>/hold.log` says `ended`.
10. **Report.** Per check: pass / fail / not reached, with its clip. Acceptance numbers: met or not met. Upload clips and frames with `--attach` (AGENTS.md "Public repo"); a failure opens an issue with its evidence attached.

Done: every check has a verdict and a clip, the INDEX row exists, `hold` matched, and the queue holds no ticket of yours.

## Asks the user first

A game update, any download, Give Up on a battle, Claim (a reward), the weekly bonus, starlight beyond the configured graces. The answer covers that one action.
