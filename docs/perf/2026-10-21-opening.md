## 每一步都多付的時間

一步的時間軸（02:49 那段，每步都一樣）：動作結束 →（0.2 s）→ `Succeeded` → HubText 讀一次字（0.1–0.3 s）→ 節點自己的 OCR ＋ `pre_delay`（0.3 s）→ 下一個動作。

- 0.2 s 是 MaaFramework 預設的 `post_delay`（每步都剛好 0.20 s）。起手的動作都已經等到下一個畫面才結束，這 0.2 s 只是讓 hub 晚看；起手約 11 步，約 2.2 秒。
- `pre_delay` 留著：PlanRun 一進來就讀每週加成的格子，TapUntil 一進來就點，頁面還在淡入時讀錯或點空的代價比 0.2 s 大。

## 一次性的等待

| 在哪 | 看到的 | 秒 | 改法 |
|---|---|---:|---|
| 最後一個 Loading → ThemePack | HubText 讀到 `NOW LOADING`，換頁後 Loading 自己的 OCR 讀不到，等滿 HubText 的 1 s 逾時，再加 HubTextLost 的 0.2 + 0.2 | 1.5–1.7（三段裡兩段） | HubText 逾時 400 ms，HubTextLost 不延遲 |
| Loading（6–9 次） | 每次 `post_delay` 500 | 平均晚看到下一頁約 0.25 | 拿掉；hub 的 `rate_limit` 300 本來就控制頻率 |
| ConfirmStarlight | 切 Convert Starlight to Cost 的 `tap(wait=1.0)`（遊戲記得上一局的開關才不用切） | 1.0 → 約 0.2 | 等勾選下面那行字換掉 |
| GiftSearchForgo | Click ＋ `post_delay` 2000 | 2.0 → 換頁的時間 | TapUntil：等 `NOW LOADING` 或主題包頁 |
| GET! 視窗 n 個 | 每個視窗關掉後回 hub，hub 再讀字、再選節點，約 0.7 s 一個 | 0.7 × (n − 1) | 見下 |

## n 個 GET! 視窗一次關掉

GiftGet 在同一個動作裡一個接一個關：點 Confirm，等到視窗消失或名牌換成下一個飾品；換了就等畫面靜止（淡出中的視窗標題還在、名牌只畫一半，會被當成下一個），再點下一個，不回 hub。

沒有不看畫面連點 n 下：最後一個視窗底下是觀測頁的飾品格（觀測之後）或起始飾品頁，多出來的一下會選到飾品。視窗一樣、名牌沒變就是點擊被吞掉，交回 hub 重看，跟以前一樣。

## 沒查的

- 「n 個 GET! 視窗能不能一次關掉（例如點空白處）」：沒有在實機試。不看畫面的點擊會落在底下的飾品格上，所以這次改成一個動作裡看到下一個名牌、等畫面靜止再點；`still()` 若因視窗光效等不到靜止，每個視窗會多等約 1.2 s 再交回 hub，實機要看；能否一次關要另外實機試。
- 記憶體：這次只改等待與 pipeline 延遲，沒有新的辨識或快取；Tasker 與 Agent 的記憶體在實機那次一起記（見 PR #211）。

## 動不了的

- MirrorEntryPaused 約 3.5 s：按 Enter 之後是遊戲的鎖鏈解開動畫（約 2.5 s）加 1 s 黑畫面，選隊頁出現後 0.2 s 內 bot 就離開（錄影逐格看）。
- Loading 共 5–7.5 s：遊戲讀取。
- 主題包難度要切換時（上一局是 HARD），02:49 那段的 `set_difficulty` 等標籤等滿 2.5 s（ThemePack 4.8 s）；NORMAL 接 NORMAL 不會發生，這次沒有改，要錄影才看得出標籤為什麼讀不到。

約 2.2（post_delay）＋ 1.6（HubTextLost，三段裡兩段）＋ 0.3（Loading）＋ GiftGet 多個視窗、Forgo、星光開關有發生時各自的量：輕負載那段 35.5 秒約降到 31–32 秒；30 秒以內要看實機（見 PR #211）。
