# 04 設定結構

本章定義使用者在 GUI 裡看到的所有設定：全域選項、出戰順序方案、星光方案、主題包方案的選擇，以及 10 支隊伍各自的欄位；也說明這些值怎麼到達 Agent、Agent 怎麼檢查，以及 Agent 自己寫的檔案（狀態檔、`runs.jsonl`）放在哪裡。遊戲資料（主題包標記、事件覆寫表、試煉風險表、選路權重）不在 PI 裡，見 [05-game-data.md](05-game-data.md)。

## 1. 總則

- 使用者設定全部放在 PI V2 的選項裡，不另外讀使用者的 YAML 或 JSON 設定檔。理由見 [ADR 0004](../adr/0004-team-settings-in-pi-with-fixed-preset-slots.md)。（#9）
- PI V2 沒有清單型選項，所以方案與隊伍都預先展開成固定數量的欄位：6 組出戰順序方案、6 組星光方案、10 支隊伍。這些數量是產生腳本裡的常數，不夠用時改常數重新產生。（#6、#9）
- `interface.json` 必須由腳本產生，不手寫。合計約 380 個控制項：全域選項 9 + 出戰順序方案 12 × 6 + 星光方案 21 × 6 + 隊伍 18 × 10 = 387。（#9、#19，[ADR 0004](../adr/0004-team-settings-in-pi-with-fixed-preset-slots.md)）
- 方案的名稱只能是固定標籤「方案 1」到「方案 6」，使用者不能自己命名。（#9）
- 出戰順序方案與星光方案放在 `global_option`，用 `setting` 分組顯示。在 MFAAvalonia 裡，`global_option` 的值存在每一份設定裡；在 MXU 裡則由所有實例共用。（#9，[ADR 0004](../adr/0004-team-settings-in-pi-with-fixed-preset-slots.md)）
- 只能使用 MXU 與 MFAAvalonia 都支援的欄位：`select`、`switch`、`input`、基本 `checkbox`、巢狀 case、`preset`、`import`、`global_option`、`setting`、`group`。不得依賴 checkbox 的 `min_count`／`max_count`、`password`、複製任務（只有 MXU），也不得依賴 checkbox case 底下的子選項（只有 MFAAvalonia）。（#6）
- 困難或普通、每週獎勵怎麼用這類策略都是 GUI 選項，不寫進狀態檔。（#8，[ADR 0003](../adr/0003-screen-is-truth-state-file-only-rotation-cursor.md)）

## 2. 值如何到達 Agent

- 選項值到達 Agent 的唯一管道是 `pipeline_override`。`PI_*` 環境變數不含選項值。（#6）
- override 是整欄替換、不深度合併，所以每個選項只寫自己專屬的節點欄位。做法是準備一批只承載值的節點，每個選項寫入其中一個節點的 `attach`，Agent 在任務開始時讀出。（#6）
- GUI 到 Agent 是單向的：Agent 不能回寫選項值，也不能動態提供選項的 cases。（#6、#9）
- Agent 必須在任務開始時檢查設定，發現錯誤就報錯並停止，不開始跑。GUI 擋不住的錯誤至少包括：（#9，[ADR 0004](../adr/0004-team-settings-in-pi-with-fixed-preset-slots.md)）
  - 同一個出戰順序方案裡，同一位罪人出現在兩個位置；
  - 沒有任何啟用的隊伍。

## 3. 介面語言

- PI 的 `languages` 欄位提供 `zh_tw` 與 `en_us` 兩種語言，對應 `interface_zh_tw.json` 與 `interface_en_us.json`，預設 `zh_tw`。（#18）
- 所有標籤與說明都寫成 `$key`，由產生 `interface.json` 的同一個腳本套用翻譯。（#18）
- 遊戲名詞保留英文原文，兩種語言都一樣：罪人名、體系、主題包、飾品、星光加成、獎勵卡種類。只翻譯 bot 自己的說明文字。（#18）

## 4. 全域選項

| 欄位 | 類型 | 值 | 預設 | 來源 |
|---|---|---|---|---|
| 難度 | select | 困難／普通／自動 | 自動 | #9、#19 |
| 跑幾局 | input（整數） | 這次啟動要完成的局數 | 1 | #8、#19 |
| 每週獎勵用法 | select | 不用／用在普通／用在困難 | 用在困難 | #9、#19 |
| 每週獎勵用量 | select | 每局只用一次／一次全用 | 一次全用 | #9、#19 |
| 每週獎勵用完就停 | checkbox | 開／關 | 未決 | #8 |
| 星光買不起時 | select | 停止／跳過這個加成 | 跳過這個加成 | #9、#19 |
| 全滅重打次數 N | input（整數） | 同一場遭遇戰最多重打幾次 | 2 | #16 |
| 重打用完後 | select | 停止／放棄這局 | 停止 | #16 |
| 失敗通知 webhook | input（網址） | 停止時送出摘要的網址；空白 = 不送 | 空白 | #14 |

規則：

- 自動難度：開局前讀入口頁的 Weekly Bonuses，還有剩就跑困難，用完改普通。（#9）
- 「跑幾局」只算 bot 這次啟動後完成的局數，不存檔。（#8，[ADR 0003](../adr/0003-screen-is-truth-state-file-only-rotation-cursor.md)）
- 「每週獎勵用完就停」的剩餘次數直接從畫面讀。（#8）
- 每週獎勵的剩餘次數從結算視窗讀；這一局五層全部通過（結算視窗顯示 `Floor 5` 且 `6/6`）時，才依用法與用量切開關再按 Claim，否則放棄獎勵。只要有一層是困難，這一局就算困難局。規則見 [03-decisions.md](03-decisions.md) 第 14 節。（#9、#17、#19）
- 全滅重打的計數以每場遭遇戰為單位，打贏就歸零。只有重打次數用完、而「重打用完後」為「放棄這局」時，才按 `Accept results` 回到地圖，再從設定面板按 Forfeit 結束這局，然後結算（[03-decisions.md](03-decisions.md#9-全滅與陣亡) 第 9 節）。停止時保存證據。（#16、#19）
- webhook 在停止時由 Agent 以 JSON POST 送出這局的摘要與證據存放路徑。MFAAvalonia 內建的通知可以另外使用。（#14、#19）

## 5. 出戰順序方案（6 組）

每組方案是 12 個有順序的下拉選單，第 1 位到第 12 位，前 7 位上場。放在 `global_option`，以 `setting` 分組。（#9）

| 欄位 | 類型 | 值 | 預設 | 來源 |
|---|---|---|---|---|
| 第 1 位 … 第 12 位 | select ×12 | `Yi Sang`、`Faust`、`Don Quixote`、`Ryōshū`、`Meursault`、`Hong Lu`、`Heathcliff`、`Ishmael`、`Rodion`、`Sinclair`、`Outis`、`Gregor` | 未決 | #9 |

- 同一位罪人出現兩次時，由 Agent 在任務開始時報錯。（#9）
- 戰前編隊時遊戲不會自動帶入出戰順序，bot 依方案重選，並跳過陣亡的罪人；做法見 [03-decisions.md](03-decisions.md)。（#9、#16）

## 6. 星光方案（6 組）

每組方案決定開局星光的購買計畫。放在 `global_option`，以 `setting` 分組。（#9）

| 欄位 | 類型 | 值 | 預設 | 來源 |
|---|---|---|---|---|
| 加成 1 … 加成 10 的等級 | select ×10 | 不買／基礎／+／++ | 未決 | #9 |
| 加成 1 … 加成 10 的優先順位 | select ×10 | 1–10 | 未決 | #9、#19 |
| 剩下的星光換成 Cost | checkbox | 開／關 | 未決 | #9 |

- 加成依遊戲星光頁的順序編號，標籤用遊戲的英文名稱。（#9、#18）

| 編號 | 加成（英文名稱） | 基礎價格（星光） |
|---|---|---|
| 1 | `Star of the Beginning` | 10 |
| 2 | `Cumulating Starcloud` | 10 |
| 3 | `Interstellar Travel` | 20 |
| 4 | `Star-shower` | 20 |
| 5 | `Binary Star-shop` | 30 |
| 6 | `Moon Star-shop` | 30 |
| 7 | `Favor of the Nebulae` | 40 |
| 8 | `Starlight Guidance` | 40 |
| 9 | `Chance Comet` | 50 |
| 10 | `Perfected Possibility` | 60 |

- 編號依星光頁上排左到右、再下排左到右。名稱與基礎價格是 Mirror of Names and Spiders 這一季的實機畫面（實機：captures/03_starlight_page.png）。
- 「基礎」是卡片本身的效果，價格標在卡片右上；「+」「++」對應卡片底部的 `+`、`++` 兩個按鈕。點卡片本身是否就選了基礎等級、「+」「++」各要多少星光，沒有實測。（實機：captures/03_starlight_page.png）
- 可用的星光是星光頁右上的 `Available`，等於選隊頁該隊的 `Starlight Bonus`，不是持有的 `Owned`。「剩下的星光換成 Cost」對應星光確認對話框的 `Convert Starlight to Cost`；不換時，剩下的星光加進這局的結算獎勵。（實機：captures/01_team_picker.png、captures/04_starlight_confirm.png）
- 依優先順位由小到大購買。（#9、#19）
- 買不起時依全域選項「星光買不起時」處理。（#9）

## 7. 主題包方案的選擇

- 主題包方案的內容（偏好／中立／避開標記）是遊戲資料，放在資料檔，見 [05-game-data.md](05-game-data.md)。PI 只提供每隊一個下拉選單「主題包方案 1–6」。（#11、#19，[ADR 0005](../adr/0005-game-data-files-separate-from-user-settings.md)）

## 8. 隊伍（10 支）

每支隊伍有下列欄位。合計每隊 18 個控制項。（#9、#10、#11、#16、#17）

| 欄位 | 類型 | 值 | 預設 | 來源 |
|---|---|---|---|---|
| 啟用 | checkbox | 開／關 | 未決 | #9 |
| 遊戲內隊伍欄位 | select | `TEAMS #1`–`#40` | 未決 | #9 |
| 主要體系 | select | `Burn`、`Bleed`、`Tremor`、`Rupture`、`Sinking`、`Poise`、`Charge`、`Slash`、`Pierce`、`Blunt` | 未決 | #9 |
| 用途 | select | 都可／只跑困難／只跑普通 | 都可 | #9、#19 |
| 第幾層起轉困難 | select 或 input | 0–5；N = 第 N 層起困難，0 = 整局困難 | 0 | #9、#19 |
| 出戰順序方案 | select | 方案 1–6 | 方案 1 | #9、#19 |
| 星光方案 | select | 方案 1–6 | 方案 1 | #9、#19 |
| 主題包方案 | select | 方案 1–6 | 方案 1 | #11、#19 |
| 獎勵卡第 1 … 5 順位 | select ×5 | `Starlight`、`Random E.G.O Gift`、`Cost & Keyword Gift Chance`、`Cost`、`E.G.O Resource` | 依此順序 | #11 |
| 商店刷新上限 N | input（整數） | 每家商店最多刷新次數 | 2 | #10、#19 |
| 治療方式 | select | 不治療／錢 ≥ 100 + 預留時全體治療／有罪人陣亡時才治療 | 有罪人陣亡時才治療 | #10 |
| 預留金額 | input（整數） | 所有花費（治療、購買、刷新）後至少留下的錢；全體治療的門檻是錢 ≥ 100 + 預留金額 | 0 | #10、#19 |
| 存活少於 K 人就停止 | input（整數） | 0–12；0 = 不檢查 | 0 | #16 |
| 試煉風險權重 | select | 低／中／高 | 高 | #17 |

規則：

- 「第幾層起轉困難」只在這一局是困難局時有效；第 N 層之前用普通。第 1 層選了困難後，之後不能切回普通。普通局第 N 層（N > 1）能不能切到困難還沒實測；不能的話這個欄位會移除（[03-decisions.md](03-decisions.md#未決)）。（#9、#19）
- 主題包方案的「方案 1」預設值由開發者每季提供。（#11）
- 獎勵卡的 5 個順位應各選一種不同的卡；比對不到任何類型時選第一張。（#11）
- 「存活少於 K 人就停止」的說明必須提醒：需要罪人陣亡的隊伍，治療方式應設為「不治療」。（#16）
- 試煉風險權重用於困難模式 Boss 後的選擇評分：飾品分數 − 權重 × 試煉風險。（#17）
- 刷新次數記在 Agent 記憶體，以層為單位，不存檔。（#10）
- 預留金額適用於所有花費：治療、購買、刷新。（#10、#19）

### 輪替

- 啟用的隊伍依編號順序各跑一局、循環下去。用途和這一局難度不符的隊伍跳過，但不推進輪替游標；沒有任何可用的隊伍就結束任務。（#9）
- 輪替游標只在 bot 親眼看到某隊完成一局並領到獎時才前進；編隊頁顯示的隊伍和游標不同時，以畫面為準。（#8，[ADR 0003](../adr/0003-screen-is-truth-state-file-only-rotation-cursor.md)）

## 9. Agent 自己寫的檔案

| 檔案 | 內容 | 用途 | 來源 |
|---|---|---|---|
| 狀態檔 | 只有輪替游標 | 跨次啟動保存下一局輪到哪一隊 | #8、#9 |
| `<root>/logs/runs.jsonl` | 每局一行：起訖時間、隊伍、難度、有沒有用每週獎勵、通過幾層、結果（通關／停止／放棄）、L1/L2/L3 各觸發幾次 | 驗收與計算整局時間上限；不用於接續判斷 | #14、#19 |
| `<root>/logs/evidence/<時間>/` | 停止時保存的證據 | 除錯與通知 | #14、#19 |

- 狀態檔只存輪替游標，其他狀態每次都從畫面讀。理由見 [ADR 0003](../adr/0003-screen-is-truth-state-file-only-rotation-cursor.md)。（#8）
- 這些檔案都必須放在 Agent 專屬的子目錄，避開 GUI 自己的檔案（`mxu-*.json`、`instances/`）。`<root>` 是 Agent 的根目錄。（#6、#19）
- 根目錄必須用 Agent 程式的 `__file__` 定位，不依賴工作目錄，因為 MFAAvalonia 的獨立資料目錄模式下工作目錄不同。（#6）
- 寫入狀態檔必須先寫暫存檔再改名，避免寫到一半損毀。（#6）

## 未決

1. 全域選項「每週獎勵用完就停」的預設值；「跑幾局」的 0 是否代表不限。
2. 隊伍欄位的預設值：啟用（例如只啟用隊伍 1）、遊戲內隊伍欄位、主要體系。出戰順序方案與星光方案各組的預設內容。
3. 星光頁上點卡片本身是否就選了「基礎」等級，以及「+」「++」各要多少星光，等實機確認。名稱與按鈕位置已確認（見第 6 節）。
4. 資料檔的主題包方案少於 6 組時 Agent 怎麼處理（任務開始時報錯，或退回方案 1）。
5. 全域選項（難度、跑幾局、webhook 等）與 10 支隊伍要放在 `global_option` 還是鏡牢任務的 option；ADR 0004 只定了方案放 `global_option`。
6. 任務開始時檢查的完整清單：除了重複罪人與沒有啟用的隊伍，是否也檢查獎勵卡順位重複、星光優先順位重複、兩支啟用隊伍用同一個遊戲內隊伍欄位等。
7. 多個實例同時執行時，狀態檔要加鎖還是每個實例一份（#6 只指出需要處理）。
8. 狀態檔所在的 Agent 專屬子目錄名稱。
