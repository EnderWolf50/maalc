# 隊伍佇列由使用者一支一支加進去，可以重複

[ADR 0014](0014-team-queue-apart-from-team-list.md) 的佇列一定是全部隊伍各一次。使用者 2026-11-25（#954）：想要的是把設定好的隊伍一支一支加進佇列，不是全部自動放入；不想出戰的隊伍要靠「停用」才會跳過；沒辦法讓同一支隊伍連續出戰或重複出現。「停用」和「起頭隊伍」都是為了繞過這個限制才有的：佇列能自己排，兩個就都不需要。

## 資料形狀

- 設定檔版本 24：`team_queue` 是 `teams` 的 id 的陣列，可以重複、可以少、可以空。陣列的一個元素是佇列的一格。不存在的 id 仍是設定檔錯誤。
- 隊伍拿掉 `enabled`，`run` 拿掉 `start_team`。
- 佇列裡不同的隊伍不能用同一個 TEAMS 欄位，同一支重複不算；不在佇列裡的隊伍不看。`target_floor` 大於 5 時的檢查也只看佇列裡的隊伍。
- 遷移 23 → 24：佇列照舊順序，去掉停用的隊伍。`start_team` 直接丟掉，不移動佇列：Agent 在記憶體裡遷移，每次讀檔都重做一次，移動的話那一隊會一直排第一。

## Agent

- 選隊：佇列裡第一格用途符合這局難度的。用途不符的跳過，留在原位。
- 領到獎勵後，這一隊在佇列裡的第一格移到最後。選隊永遠選到該隊的第一格，所以不必記住打的是哪一格：檔案裡同一支隊伍的格子彼此沒有差別。隊伍在這局中被移出佇列時不動，記一行。
- 佇列是空的：鏡牢任務以成功結束（不打、回主畫面、記一行），和沒有可用的隊伍同一條路（#364）。佇列是空的、卻有一局在跑時，推不回隊伍，走停止程序，和以前沒有啟用的隊伍時相同。
- 檔案還是舊版本時，照原本的版本與格式寫回（版本 22、23 改 `team_queue`，版本 20、21 改 `teams` 的順序），停用的隊伍留在原位。

## 設定視窗

- 佇列下面一顆「＋ 加入隊伍」，和任務清單的「加入任務」同一種操作（使用者選的 A 版）。每一列有「排到最上面」與 ✕；移出可以復原，和任務清單的移除一樣。「排到最上面」取代起頭隊伍的旗子：它只排一次，不會每次開始任務都重排。
- 新建的隊伍不自動進佇列。刪除隊伍時，它在佇列的每一格都移除，復原時都回到原位。
- 合併（視窗開著時 bot 移動了佇列）照 ADR 0011，移動的單位改成格：找出最少幾次「某隊的第一格移到最後」能把視窗讀到的佇列變成檔案的佇列，在未存的修改上照做一遍。檔案的佇列多了或少了格子時不是移動，保留修改。

## Considered Options

- **左邊全部隊伍、右邊佇列兩欄**（B 版）：使用者選了 A 版，B 佔的寬度較多。
- **每一格存成物件、各有自己的 id**：能分辨同一支隊伍的兩格，但兩格沒有任何差別，分得出來也沒有用處；設定檔和合併都變複雜。
- **遷移時照起頭隊伍移動佇列**：見「資料形狀」，記憶體裡的遷移會每次重做。
- **兩種難度各一份佇列**、**打完就從佇列消掉**：使用者決定不做（#954 範圍外）。

## Consequences

- 取代 ADR 0014 的「`team_queue` 必須剛好是 `teams` 每個 id 各一次」、「停用的隊伍留在佇列原位」、「新增隊伍加在 `teams` 和 `team_queue` 的最後」與「起頭隊伍」一節。佇列與隊伍清單分開、Agent 只寫佇列、比對後交換，都不變。
- 修訂 [ADR 0015](0015-settings-window-runs-the-tasks.md)：`run` 沒有 `start_team`，鏡牢任務的選項是 10 個；MXU 的 `MirrorStartTeam` 不讀回。
- 升級後，停用的隊伍只是不在佇列裡；重新加入是使用者的事。
- 舊版 Agent 讀到版本 24 會報「比自己新」。
