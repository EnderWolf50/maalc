# 隊伍佇列和隊伍清單分開，存在 `team_queue`

[ADR 0011](0011-team-list-order-is-the-queue.md) 讓設定視窗隊伍頁的清單順序就是隊伍佇列。這帶來三個問題（#802）：清單不能照自己的習慣整理，拖曳一支隊伍就改了下一局輪到誰；bot 每領一次獎勵就把那支隊伍移到清單最後，使用者打開設定視窗時清單的順序常常和上次不同；輪替這個功能看不出來在哪裡，說明只有清單上方一行灰字，也沒有地方寫下一局輪到誰。使用者 2026-11-16 決定：隊伍佇列和隊伍清單分開；佇列放在設定視窗；MXU／MFAAvalonia 的鏡牢任務只加一個選項，選這次從哪一支隊伍開始；不加輪替開關；做完再發 v1.0.0。

## 資料形狀

- 設定檔版本 22 加頂層欄位 `team_queue`：隊伍 id 的陣列，順序就是隊伍佇列。`teams` 的順序只是隊伍清單的顯示順序，選隊不看它。
- `team_queue` 必須剛好是 `teams` 每個 id 各一次，順序不限。不符時，設定視窗和 Agent 都當成設定檔錯誤，訊息說明哪個 id 多了、重複了，或哪一支隊伍不在佇列裡（`tests/settings_cases.json` 的共用案例）。只有手改檔案會弄出這種錯，所以設定視窗的訊息指向設定檔的 `team_queue`。
- 停用的隊伍留在佇列原位。選隊跳過它，和用途不符時一樣，重新啟用後它回到原來的順位。
- 遷移 21 → 22：`team_queue` 照 `teams` 當時的順序建立，其他不變，所以升級後輪到誰不變。Agent 在記憶體裡遷移；設定視窗遷移後寫回，舊檔另存成 `config/settings.v21.json`。版本 20 的檔一次遷移到 22，版本 20 的提示照舊只出現一次。21 → 22 沒有提示：遷移不會讓任何值失效。

## Agent

- 選隊、接續的局推回隊伍、領獎後移到最後、舊狀態檔的游標遷移，都改照 `team_queue` 的順序。規則本身照 ADR 0011：第一支啟用、用途符合這局難度的隊伍出戰；確認領到結算獎勵才移到最後。
- Agent 唯一會寫的仍是設定檔裡的佇列：只改 `team_queue`，`teams` 的順序和其他內容照原樣。寫法照 ADR 0011：先重讀檔案，比對後交換，被搶先就重讀再試，最多 3 次。
- 磁碟上的檔案還是版本 20 或 21（設定視窗還沒寫回）時，它的佇列就是 `teams` 的順序：Agent 照舊在 `teams` 裡移動，以檔案原本的版本寫回（[04](../spec/04-settings.md) 第 2 節）。設定視窗寫回時，遷移再從這個順序建立 `team_queue`。

## 設定視窗

- 新增隊伍加在 `teams` 和 `team_queue` 的最後；刪除隊伍從兩者移除，復原時兩邊都回到原位。
- 隊伍清單的拖曳與 ↑↓ 只改 `teams`。清單不再標順位，也拿掉「清單順序就是隊伍佇列」那行說明；佇列在隊伍頁的「隊伍佇列」區塊顯示與調整（#804）。
- bot 在視窗開著時改了佇列，照 ADR 0011 合併，只是對象從 `teams` 的順序改成 `team_queue`：沒有未存修改就直接採用檔案；有未存修改就保留修改，再把檔案裡移到最後的隊伍也移到最後（`movedToEnd`）。

## 起頭隊伍（#805）

鏡牢任務的 client 選項 `MirrorStartTeam` 選這次從哪一支隊伍開始，預設「照隊伍佇列」（不送值）；選了隊伍時，值以 `start_team` 送到入口節點的 `attach`。

- 任務開始時（點任何東西之前）：隊伍已刪除或停用就停下，訊息點名這個選項和隊伍。
- 任務要開第一局新局時，在選隊之前把這支隊伍移到 `team_queue` 第一，寫法和領獎後相同，並記一行：已排到第一，或本來就在第一。移到第一等於把排在它前面的隊伍依序移到最後，所以設定視窗的合併不用改。
- 任務開始時已經有一局在跑（Agent 重開、接續暫停的局、領上一局的獎勵）：這一局照移動前的佇列推回隊伍，起頭隊伍等下一局新局才排。
- 起頭隊伍的用途不符合這一局的難度：照常往後找第一支符合的隊伍，記錄寫明起頭隊伍因為用途被跳過；它留在佇列第一。
- client 會記住選擇，之後每次開始任務都會再排一次，所以平常應該留「照隊伍佇列」。

## Considered Options

- **清單順序仍是佇列，另外標出下一局輪到誰**：輪替找得到了，但拖曳整理仍會改到下一局，bot 也仍會重排清單。
- **每支隊伍一個 `queue_position` 數字**：每次領獎要改好幾支隊伍的數字，數字重複或跳號還要另外修。陣列移動一個元素就好，規則也只有「每個 id 各一次」一條。
- **佇列放在 Agent 自己的檔案**：設定視窗也要編輯佇列，就多一個兩邊都寫的檔案，比對後交換和合併要再做一份。放在同一份設定檔，沿用 ADR 0011 的寫法。
- **在 client 裡拖曳排佇列，或在 client 上顯示下一局輪到誰**：做不到。client 選項沒有清單型別，選項也只能從 client 單向傳給 Agent（ProjectInterface V2 的選項型別），Agent 寫不回 client 的設定。所以 client 只放起頭隊伍這一個下拉選單。
- **輪替開關**、**困難與普通各一份佇列**：使用者決定不做（#802 範圍外）。

## Consequences

- 取代 ADR 0011 的「清單順序就是佇列」與「設定檔格式不變，不升版本」。ADR 0011 其餘決定不變：領獎才移動、比對後交換、設定視窗的合併、舊狀態檔游標的遷移。
- 修訂 [ADR 0006](0006-settings-gui-writes-one-settings-file.md)：Agent 的例外改成只寫 `team_queue`（版本 20、21 的檔照舊只改 `teams` 的順序）。
- 舊版 Agent 讀到版本 22 會報「比自己新」。
- 隊伍清單上的位置不再代表輪到的先後，「隊伍佇列」區塊才是（#804）。
