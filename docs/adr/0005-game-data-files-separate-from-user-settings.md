# 遊戲資料放在資料檔，與 PI 的使用者設定分開

每一季鏡牢都會換主題包和事件，例如 Mirror of Names and Spiders 只到 2026-10-15。如果把主題包清單、事件處理方式、飾品清單這類**遊戲資料**展開成 PI 選項，每季都要重新產生 `interface.json`，選項數量也會爆炸（約 95 個主題包 × 每隊）。所以遊戲資料放在 resource 裡的資料檔，由開發者每季更新，使用者可以自己修改。**使用者設定**（隊伍、方案的選擇、全域行為）照 ADR 0004 放在 PI。

具體包括：

- **主題包方案**：一份「偏好／中立／避開」標記表，可以有多組。每隊在 PI 用下拉選單選擇「主題包方案 1–N」。開發者每季提供方案 1 的預設值。
- **事件覆寫表**：只放例外，格式是「問題文字 → 選哪個選項」，一開始是空的。所有事件都先照通用規則處理。這和 M9A 為每個事件寫動作腳本不同，因為事件約有 70 個，而且每季會換。

## Consequences

- 換季時只要更新資料檔，不必重新產生 `interface.json`。
- 想調整主題包偏好的使用者要編輯檔案；選擇每隊用哪個方案，仍然在 GUI 裡。

## 修訂（ADR 0006）

[ADR 0006](0006-settings-gui-writes-one-settings-file.md) 把使用者設定從 PI 移到自製設定 GUI 寫的設定檔。遊戲資料和使用者設定分開這點不變，但有三處改變：（#19，2026-10-14 定案）

- 主題包方案拆成兩種：每季的「預設」方案留在資料檔，使用者不能改；使用者自己的方案存在設定檔，名稱自取、數量不限。
- 事件覆寫與試煉風險覆寫改在 GUI 的表格裡編輯，存在設定檔，疊加在資料檔上。不再有另外的覆寫檔，使用者也不直接改資料檔。
- 上文的 `interface.json` 與 PI 選項已不適用。
