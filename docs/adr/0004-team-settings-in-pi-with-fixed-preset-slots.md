# 隊伍設定全部放在 PI，用固定數量的方案欄位共用設定

隊伍、出戰順序與星光都要能在 GUI 裡設定，而且多支隊伍要能共用同一組出戰順序或星光方案。PI V2 沒有清單型選項，也不能讓使用者自己建立具名 preset：`preset` 是開發者寫死的快照，選項的 cases 在載入時就固定了。所以我們預先開出固定數量的欄位：6 組出戰順序方案、6 組星光方案（放在 `global_option`，並用 `setting` 分組顯示），以及 10 支隊伍；每支隊伍用下拉選單選擇要用哪一組方案。

## Considered Options

- **隊伍與具名方案都放在 Agent 的 YAML 檔**：可以隨意命名、數量不限，但沒有 GUI，打錯只能在執行時報錯。不採用。
- **每支隊伍各自展開所有欄位、不共用**：每隊約 38 個控制項，10 隊約 380 個，而且改一處要改每一隊。不採用。

## Consequences

- 合計約 380 個控制項（#10 在每隊加了刷新上限、治療方式、預留金額；#11 加了主題包方案的選擇和 5 個獎勵卡優先順序；#16 加了存活門檻，#17 加了試煉風險權重），`interface.json` 用腳本產生，不手寫。組數和隊數是腳本裡的常數，不夠用時改數字重新產生。
- 方案名稱只能是「方案 1」到「方案 6」這類固定標籤。
- 在 MFAAvalonia 裡，`global_option` 的值存在每一份設定裡，不像 MXU 是所有實例共用。
- 「第 1 位和第 5 位都選同一人」這類錯誤 GUI 擋不住，由 Agent 在任務開始時檢查並報錯。
- Agent 的狀態檔仍然只存輪替游標（ADR 0003）。
